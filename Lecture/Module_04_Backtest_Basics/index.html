模組 04

回測入門

lo2cin4bt 的回測不只畫資金曲線。系統讀取策略設定，載入資料， 產生計算欄位（computed fields）、訊號（signals）或目標權重（target weights），並按時間計算現金、 持倉、市值、費用、換手率（turnover）、資金曲線（equity）與比較基準（benchmark）。

選設定檔（config） 載入資料 產生訊號 / 權重 按時間記帳 輸出產物（artifacts） 前端閱讀

回測工作流程（Backtest Workflow）

指標、訊號、排名、權重、成交與記帳都由 Rust 正式路線處理；Python 只驗證輸入、載入資料與協調流程。

Rust 計算邊界

所有會改變回測結果的計算，包括指標（indicator）、訊號（signal）、選股（selection）、排名（ranking）、目標權重（target weights）、成交（fills）、 記帳（accounting）、風控事件（risk events）與指標（metrics），都由 Rust 擁有。Python 控制層只負責結構綱要（schema）驗證、資料載入、 引擎請求（EngineRequest）組裝、服務協調及將已驗證產物交給前端；不存在另一條 NumPy 回測路線。

單資產如何進入統一引擎

單資產策略會被視為「只有一個資產的投資組合」。例如 QQQ 均線策略： 入場訊號把 QQQ 目標權重（target weight）設為 100%，離場訊號把目標權重設為 0%。 這樣它可以與多資產投資組合共用同一套資金曲線（equity）、費用（fee）、換手率（turnover）、風控門檻（risk gate）與不變條件（invariant）檢查。

實務操作順序

  1. 啟動平台 執行 python main.py，打開 http://127.0.0.1:2424/。
  2. 在執行中心（Run Center）選擇設定檔 從 workspace/runs/ 選擇回測設定檔（backtest config）。由 platform.workflow_id 設定 parameter_matrix 或 single_backtest。不要從檔名或參數有無推斷。
  3. 閱讀指標總覽（Metrics Overview） 先看資金曲線（equity）、比較基準（benchmark）、總報酬（Total Return）、年化複合成長率（CAGR）、夏普比率（Sharpe）、最大回撤（MDD）及卡瑪比率（Calmar）。
  4. 進入回測詳情（Backtests） 檢查策略表（Strategy Table）、已選策略摘要（Selected Strategy Summary）、投資組合背景（Portfolio Context）、風控門檻稽核（Risk Gate Audit）及配置變化（Allocation Changes）。

回測前檢查

設定檔結構綱要（Config schema）只接受現行 strategy_run 契約（contract）；舊設定檔（config）不會自動映射或補欄位。
資料完整性確認資產、比較基準（benchmark）、頻率及有效起始日都能載入。
參數範圍（Parameter domain）parameter_matrix 需要非空參數範圍；空物件會成為沒有參數範圍（no-domain）狀態。single_backtest 的標準寫法是 {}。
驗證選擇固定配置可做單次回測。跨時段檢查要選擇滾動驗證（Rolling Validation），系統不會附加該工作。

目前回測流程

回測使用同一條路： strategy_run 產生訊號、選股、再平衡或目標權重； fill_model.timing = "timeline" 安排成交時間； 統一時間線記帳（unified timeline accounting）計算現金、持倉、成本、換手率（turnover）、資金曲線（equity）和稽核（audit）。

執行中心（Run Center）顯示可執行設定檔（config）；指標總覽（Metrics Overview）、參數矩陣（Parameter Matrix）、回測詳情（Backtests）及前向分析（WFA）顯示已完成執行（run）的產物（artifacts）。 如果 outputs/app/latest_runs.json 是空陣列，即使 workspace/runs/ 有設定檔， 結果頁沒有資料列（row）代表沒有完成執行，需要先進行回測。
