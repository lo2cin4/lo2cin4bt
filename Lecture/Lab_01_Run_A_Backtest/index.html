lo2cin4bt 課程實驗 01

實驗（Lab）01

跑一個本機回測

這個實驗（Lab）使用一份現有 strategy_run 設定檔（config）。你會建立本機產物，並在瀏覽器檢查結果。

學習目標

本實驗會完成甚麼

你會跑一次回測、找到 run_id、分辨比較頁與細節頁，最後確認產物結構完整。

i

未用過平台？
請讀模組（Module）00。能打開 2424 的讀者可由步驟 1 開始。

▶

人工操作路線（Manual route）

人工操作版

1

啟動平台

執行 python main.py，打開 http://127.0.0.1:2424/。

預期結果：看到 lo2cin4bt 側邊欄與總覽頁。

常見問題：連線被拒絕代表服務未啟動，先看終端錯誤，唔好改前端路由。

2

在執行中心（Run Center）選擇設定檔

打開執行中心，選擇 workspace/runs/ 內一份回測設定檔（Backtest config）。

預期結果：畫面顯示策略名稱、流程、資料來源與執行按鈕。

常見問題：清單為空時，確認範例是否已初始化至 workspace/runs/。

3

執行並等待完成

按執行，留意資料載入（dataloader）、回測（backtester）、驗證（valid）、績效計算（metricstracker）與繪圖資料（plotter）各階段。

預期結果：工作顯示完成，並產生新的 run_id。

常見問題：任何階段失敗都應讀原始錯誤與階段（stage），不應加例外跳過。

4

閱讀兩種結果頁

指標總覽（Metrics Overview）比較候選。回測詳情（Backtests）顯示單一結果的曲線、交易、配置、成本與風險。

預期結果：兩頁使用同一份已驗證結果套件（validated result bundle），主要指標一致。

常見問題：若一頁有值，另一頁為不適用（n/a），問題位於前端資料與契約（payload / contract），不代表策略沒有數據。

◆

人工智能輔助路線（AI-assisted route）

代理與技能版（Agent / Skill）

你提供指令，人工智能（AI）負責操作平台。專案經理（ProjectManager）理解任務，lo2cin4btWorkAgent 執行，技能（Skill）提供步驟與驗收規則。

請先閱讀 agents/lo2cin4bt_PM.agent.md 和 skills/lo2cin4bt/SKILL.md。
這次任務請由 lo2cin4btWorkAgent 使用 lo2cin4bt-backtesting。
目標：選擇 workspace/runs/ 內一份回測設定檔（Backtest config），完成本機回測，列出 run_id、設定檔（config）、前端資料（payload）和輸出路徑。
完成後使用 lo2cin4bt-acceptance 檢查 dataloader -> backtester -> valid -> metricstracker -> plotter。
不要做實盤交易，不要連接經紀商（broker）下單。
預期結果

人工智能（AI）回報所用設定檔（config）、run_id、各階段（stage）狀態、結果頁與驗收命令，而不是只回答「完成」。

常見問題

若人工智能沒有讀代理與技能（Agent / Skill）便改碼，請停止工作，並要求它列出程式庫（repo）證據及工作流程。

完成核對清單（Checklist）

瀏覽器會保存勾選狀態。「複製清單」按鈕可複製任務清單。

  • 執行中心（Run Center）顯示批次（batch）完成，並有新的 run_id
  • outputs/app/run_registry/ 有對應登錄資料（registry）
  • outputs/app/chart_payloads/<run_id>/ 有前端資料（payload）
  • 指標總覽（Metrics）或回測詳情（Backtests）頁能打開最新結果
  • 若失敗，先記下設定檔路徑（config path）、階段（stage）、錯誤訊息和日誌路徑（log path），不要改策略結論
▲

如果結果頁沒有資料

執行中心（Run Center）讀到 workspace/runs/ 的設定檔（config），只代表可以選擇和執行策略。 指標總覽（Metrics Overview）、參數矩陣（Parameter Matrix）、回測詳情（Backtests）和前向分析（WFA）頁面顯示已完成執行紀錄（run）的結果。 如果 outputs/app/latest_runs.json 是 []， 執行中心尚未建立可顯示的完成結果。

新範例應優先使用 strategy_run，成交假設用 fill_model.timing = "timeline" 和 actions[] 表達。

  1. 確認執行中心（Run Center）顯示完成，而不是排隊或失敗。
  2. 打開 outputs/app/stage_status/，找對應 run_id 的失敗階段（stage）。
  3. 檢查 outputs/app/run_registry/ 與 outputs/app/artifact_manifests/ 是否同時存在。
  4. 若執行紀錄（run）已完成但 outputs/app/latest_runs.json 是空陣列，請執行登錄資料（registry）驗收。不要手動建立最新執行紀錄（latest run）。

專案證據

  • workspace/runs/
  • outputs/app/run_registry/
  • outputs/app/chart_payloads/<run_id>/
  • skills/lo2cin4bt-backtesting/SKILL.md
