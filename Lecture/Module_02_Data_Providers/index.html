模組 02

資料來源與安裝要求

lo2cin4bt 的資料由資料載入器（dataloader/）載入。回測器（Backtester）、前向分析（WFA）與前端不會呼叫經紀商（broker）、 交易所（exchange）或外部資料介面（API）。這個邊界讓策略、回測與前端報告共用同一套資料健康檢查。

資料如何進入回測

flowchart LR
  Request["設定檔資料區段（config data section）
資料來源／資產代號／比較基準（provider / symbols / benchmark）"] --> Adapter["資料載入轉接器（dataloader adapter）"]
  Adapter --> Standard["標準開高低收量（OHLCV）
日期／開市價／最高價／最低價／收市價／成交量（date / open / high / low / close / volume）"]
  Standard --> Health["資料健康（data health）
有效起始日／缺失資產（effective start / missing assets）"]
  Health --> Cache["快取與受管產物（cache / managed artifacts）"]
  Cache --> Engine["回測器與前向分析（backtester / WFA）"]
  Health --> Rules["策略規則（Strategy Rules）
前端可讀摘要"]

不同資料來源的差異留在轉接器（adapter）；引擎只處理標準化後的資料與資料健康報告。

正式資料來源規則

資料來源（provider） 用途 資產代號例子 可用行情週期 需要什麼 常見錯誤
雅虎財經（yfinance） 公開每日指數股票型基金（ETF）及股票資料。 QQQ、SPY、VOO 只接受日線。分鐘或小時要求會停止，不會改用其他週期。 pyproject.toml 及 uv.lock 鎖定的 yfinance / curl_cffi。 資產代號不存在、雅虎財經（Yahoo Finance）缺資料、比較基準與策略市場不一致。
幣安（binance） 加密資產現貨 K 線（crypto spot kline）。 BTCUSDT、ETHUSDT 1、3、5、15、30 分鐘；1、2、4、6、8、12 小時；1 日。 python-binance、網絡與時間週期。 不會在未說明下改用雅虎財經（Yahoo Finance）比較基準；幣安（Binance）資產代號（symbol）不使用連字號。
Coinbase 交易所（coinbase） Coinbase 交易所（Coinbase Exchange）公開 K 線資料。 BTC-USD、ETH-USD 1、5、15 分鐘；1、6 小時；1 日。 dataloader/market_data_loader.py、網絡、Coinbase 產品代號（product）格式。 Coinbase 交易所使用 BASE-QUOTE 格式，不使用幣安（Binance）的 BTCUSDT 寫法。
本地檔案（file） 本地逗號分隔檔（CSV）或 Parquet 檔案。 本地路徑與資產代號對應 依檔案聲明的行情週期契約（bar_time）。 事件時間、開高低收量（OHLCV）、交易時段、可用時間與品質規則。 欄位名不一致、日期不是交易日、缺少比較基準（benchmark）或未說明價格調整（adjustment）。
富途（futu） 富途開放閘道（Futu OpenD）轉接器框架。 依富途市場前綴（Futu market prefix） 1、5、15、30 分鐘；1 小時；1 日。 futu-api、富途開放閘道（Futu OpenD）、主機位址與連接埠（host / port）、行情權限。 套件裝好不等於開放閘道（OpenD）已開，也不等於有行情權限。
盈透證券（IBKR） 盈透證券交易工作站或閘道（TWS / IB Gateway）轉接器框架。 依盈透證券合約（IBKR contract）及資產代號對應 1、5、15、30 分鐘；1 小時；1 日。 ib-insync、交易工作站或閘道（TWS / Gateway）、已啟用應用程式介面（API enabled）、連接埠（port）及行情權限（market-data entitlements）。 閘道（Gateway）未開、應用程式介面連接埠（API port）錯誤或行情權限（market-data entitlement）不足。

富途與盈透證券的轉接器及週期契約已有測試；用戶電腦上的閘道、登入狀態與行情權限仍要在執行前核對，不能由程式庫測試代替。

比較基準（benchmark）原則

  • 單資產策略可由同一資料來源的買入持有推導。設定檔（config）仍應寫入比較基準（benchmark）。
  • 多資產投資組合（portfolio）要指定比較基準（benchmark），例如 SPY、BTCUSDT 或同市場代表資產。
  • 加密資產（crypto）資料來源不會在未說明下切到雅虎財經（Yahoo Finance）資產代號（ticker）。跨資料來源使用比較基準（benchmark）時，人工智能（AI）會向用戶說明。
  • 若比較基準缺少資料，報告會影響比較基準報酬（Benchmark Return）、超額報酬（Excess Return）及與比較基準相關性（Benchmark Correlation）。

資料健康（Data Health）解讀

缺資料、重複時間或時間次序錯亂會令執行停止。執行中心會顯示結構化失敗資料（run_failure.v1），人工智能也應據此指出供應者、資產、週期與失敗規則；系統不會補造資料或改用另一來源。

有效起始日（Effective Start）

所有必要資產、比較基準（benchmark）及計算欄位（computed fields）可共同開始的日期。多資產會被最晚可用資產拖後。

已載入資產（Loaded Assets）

載入成功的資產。請與資產範圍（universe）對照。

缺失資產（Missing Assets）

要求但未成功載入的資產。名單有內容時，請檢查資料缺口。

資料來源錯誤（Data Provider Error）

例如端點、閘道程式、權限、資產代號或時間週期問題。這不是策略邏輯錯誤。
