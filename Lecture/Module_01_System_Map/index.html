模組 01

系統地圖

lo2cin4bt 使用一條回測主線。策略種類只會改變設定檔（config）內容，不會建立另一個回測引擎。

正式回測流程

flowchart LR
  Config["策略執行設定檔（strategy_run config）"] --> Normalize["Python 設定正規化與驗證"]
  Data["市場資料載入器（dataloader）"] --> Request["引擎請求與市場資料套件（EngineRequest + MarketDataBundle）"]
  Normalize --> Request
  Request --> Rust["持續運行的 Rust 引擎服務（engine_service）"]
  Rust --> Result["標準結果套件（CanonicalResultBundle）"]
  Result --> Validate["Rust 強制結果驗證"]
  Validate --> Metrics["Rust 績效指標與繪圖套件（metrics + PlotBundle）"]
  Metrics --> Artifacts["應用程式產物與索引（outputs/app）"]
  Artifacts --> API["應用程式介面（app API）"]
  API --> UI["前端介面（plotter/web :2424）"]
  Config -. "工作流程（workflow）選擇前向分析（WFA）或滾動驗證（rolling validation）" .-> WFA["驗證工作流程（validation_workflow）"]
  WFA --> Request
  Artifacts -. "可選診斷" .-> Stats["統計分析器（statanalyser）"]

Python 控制層負責安排工作、載入資料和保存產物；Rust 計算核心負責所有會改變回測結果的運算。

各層責任

模組用途不可做的事
資料載入器（dataloader/）讀取、對齊及標記市場資料來源。不可自行計算策略回報。
回測控制層（backtester/）把公開設定檔（config）正規化成共享 Rust 請求（Rust request），並管理持續運行的 Rust 服務。不可為每個策略家族新增獨立執行路線。
Rust 計算核心（rust/lo2cin4bt_core/）計算指標、訊號、持倉、成交、成本、風控、資金曲線、績效指標（metrics）及繪圖套件（PlotBundle）。未通過強制結果驗證器（result validator）的結果不可交給前端。
驗證工作流程（validation_workflow/）設定檔（config）選擇前向分析（WFA）或滾動驗證（rolling validation）時負責編排。不可把參數矩陣（Parameter Matrix）或普通回測當成前向分析（WFA）。
統計分析器（statanalyser/）提供可選的研究診斷。不可成為正式回測、績效指標（metrics）或前端的必經依賴。
應用程式介面與前端（app/api/／plotter/web/）讀取同一份已驗證結果並展示。前端不可重算或補造回測語義。

策略如何共用同一引擎

選股擇時投資組合（selection_timing_portfolio）、資產配置投資組合（allocation_portfolio）、輪動投資組合（rotation_portfolio）、日曆事件投資組合（calendar_event_portfolio）與配對價差投資組合（pair_spread_portfolio）都屬於設定檔範本（config profile）。系統會把各設定檔範本驗證及編譯成同一種引擎請求（EngineRequest），再交給同一個 Rust 引擎（Rust engine）。單資產策略可視為只持有一項資產的投資組合。
