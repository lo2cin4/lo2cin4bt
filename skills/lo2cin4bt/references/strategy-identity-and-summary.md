# Strategy Identity And Summary Contract

Use this contract whenever an AI agent creates, reviews, runs, or explains a
`strategy_run` config. It keeps the short result name and the detailed strategy
logic tied to the same executable source without duplicating strategy behavior
in prose.

## Source Of Truth

The user's natural-language request is an authoring input, not a runtime
contract. The Strategy Builder must translate it into a complete
`strategy_run` config. After validation, the normalized config and the
app-managed `outputs/app/run_snapshots/<run_id>/strategy_run.json` snapshot are
the source of truth.

The frontend does not ask an AI to rename or reinterpret a completed run:

```text
user request
-> AI-authored strategy_run
-> validator and normalizer
-> immutable run snapshot
-> deterministic result name and strategy-logic projection
```

## Authoring The Short Name

Set `platform.display_label` using this shape:

```text
<assets> | <strategy concept> | <provider>
```

Example:

```text
VOO-GLD | 90D Momentum 250D SMA Filter | yfinance | Example
```

Rules:

- `<assets>` must agree with `universe.symbols`; use ticker symbols, not
  `MULTI`, `Portfolio`, or a strategy-family name.
- `<strategy concept>` must summarize the distinguishing decision rule in plain
  language. Prefer `Daily SMA Cross`, `90D Momentum 250D SMA Filter`, or
  `Monthly Pair Spread Same Session` over generic labels such as `Factor`,
  `Selection`, `Multi-Leg`, or `Strategy`.
- `<provider>` must agree with `data.provider`.
- `<run type>` describes authoring intent such as `Example`, `Test`, or
  `Production`; it is not the workflow.
- Do not include `Backtest`, `Workflow`, a date, `run_id`, `Parameter Matrix`,
  or `Single Backtest`. The application adds execution identity itself.
- Keep `metadata.strategy_id` as a stable machine slug. Do not use it as the
  human-facing strategy name.
- The short name never controls execution. If it disagrees with the structured
  fields, the structured fields remain executable truth and the config must be
  revised before acceptance.

The result selector is generated as:

```text
<run date> | <assets> | <strategy concept> | <workflow> | run <short id>
```

The run date and short id are generated by the app. Assets come from
`universe.symbols`, the concept comes from `platform.display_label`, and the
workflow comes from `platform.workflow_id`.

## Authoring Detailed Strategy Logic

Do not write a second free-text strategy description for the frontend. Encode
the complete strategy in structured fields:

- `universe.symbols`: tradable assets
- `computed_fields`: indicators and derived values
- `signals`: entry, exit, state, and conflict rules
- `selection`: eligibility, ranking, and top-N rules
- `allocation`: target weights and cash policy
- `rebalance`: schedule or event trigger
- `fill_model`: timing, price, ordered actions, position policy, costs, slippage
- `risk`: position, exposure, shorting, and risk-gate limits
- `parameter_domains`: fixed search ranges

The app normalizes the config and deterministically projects these fields into
the Strategy Logic panel. `metadata.notes` may explain research context but
must not contain behavior that is absent from the executable fields.

## Required Strategy Builder Preview

Before calling a config runnable, return both:

```text
result_selector_preview:
  <assets> | <strategy concept> | <workflow>
strategy_logic_preview:
  universe: ...
  indicators: ...
  signals/selection: ...
  allocation/rebalance: ...
  execution actions: ...
  costs: ...
  risk: ...
  parameter domains: ...
```

The preview must be derived from the config just written, not copied from the
original user message. If the preview cannot reproduce the user's strategy
precisely, return `needs_clarification` or revise the config.

## Validation Checklist

- `platform.display_label` follows the four-part authoring shape.
- Assets and provider agree with their structured fields.
- The strategy concept is specific and contains no generic family-only label.
- No executable rule exists only in `display_label` or `metadata.notes`.
- The normalized strategy-logic preview includes universe, decision,
  allocation, execution, costs, risk, and parameters where applicable.
- After an app-managed run, `/api/app/metrics/runs` shows the expected selector
  identity and the run snapshot contains the exact reviewed config.
